# Gabarit 0.1 — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publier `gabarit@0.1.0` — tokens, `IconRegistry` et les 11 composants d'interface extraits de Hangar — puis migrer Hangar dessus et supprimer son dossier `frontend/src/app/ui/`.

**Architecture:** Workspace Angular à un seul projet de type librairie, construit par `@angular/build:ng-packagr`, catalogué par Storybook. Les composants sont extraits de `Hangar/frontend/src/app/ui/` sans refonte d'API : ils sont déjà `standalone`, en signaux et `OnPush`. Le travail réel se limite à trois transformations — renommer le sélecteur, externaliser les chaînes visibles, remplacer le dictionnaire d'icônes figé par un registre injectable.

**Tech Stack:** Angular 22.1, TypeScript 6.0, SCSS, `@angular/build:unit-test` (vitest intégré), ng-packagr, Storybook (`@storybook/angular-vite`), npm 12.

**Spec:** `docs/superpowers/specs/2026-08-29-gabarit-design.md`

**Source d'extraction :** `~/Projects/Hangar/frontend/src/app/ui/` et `~/Projects/Hangar/frontend/src/styles/tokens.scss`. Ces fichiers ne sont pas modifiés avant la tâche 9.

## Global Constraints

- **Dépendances du workspace** : Angular `^22.1.0`. **Plage peer de la librairie** : `^22.0.0` — une plage peer déclare ce que la librairie supporte, pas ce avec quoi le workspace est construit, et rien dans Gabarit n'utilise d'API propre à 22.1. Angular n'est jamais en `dependencies` de la librairie ; seule dépendance runtime autorisée : `tslib ^2.3.0`.
- TypeScript `~6.0.2`, npm `12.0.1`.
- Licence **MIT**. Paquet npm `gabarit`, version `0.x` — **aucune promesse de semver avant la 1.0**, à écrire dans le README.
- Préfixe de sélecteur : **`gbt-`**.
- **Les identifiants globaux, eux, se renomment** : noms de `@keyframes` (Angular ne les encapsule pas — vérifié dans le bundle publié), identifiants DOM générés (`hg-input-${n}`, `hg-tab-panel-`…) qui relient `label`/`aria-labelledby` à leur cible, et classes utilitaires globales. Tout ce qui sort de l'encapsulation de vue porte le préfixe `gbt-`.
- **Ne jamais renommer les classes CSS des composants.** Elles sont encapsulées par Angular (`styleUrl` + encapsulation par défaut) et ne fuient pas. Un `sed s/hg-/gbt-/g` global est une erreur : il toucherait `hg-modal__close`, `hg-select__chevron`, etc., sans aucun bénéfice et avec un risque de désynchroniser HTML et SCSS. Seuls changent : les sélecteurs de composants, les identifiants DOM générés (`hg-tab-panel-` → `gbt-tab-panel-`), et les classes utilitaires **globales** (`.hg-form-error` → `.gbt-form-error`).
- Tout composant est `standalone`, utilise `input()` / `output()`, et `ChangeDetectionStrategy.OnPush`.
- **Aucune chaîne visible en dur.** Toute chaîne affichée ou lue par un lecteur d'écran est une entrée du composant. Défaut en anglais quand un défaut a du sens, aucun défaut sinon. Gabarit n'embarque pas `transloco`.
- **Accessibilité : RGAA 4.1.2** (version en vigueur, 106 critères, alignée WCAG 2.1 AA / EN 301 549), plus les ajouts AA de WCAG 2.2 que le RGAA 5 intégrera fin 2026 : **2.4.11** focus non masqué et **2.5.8** cible de pointage de 24 × 24 px minimum. Le contraste du texte vise **AAA (7:1)** — au-delà de l'obligation, choix assumé. Le contraste des composants et éléments graphiques reste à **3:1** (critère 3.3), qui n'a pas de niveau AAA.
- **Stories** : importer `Meta`, `StoryObj`, `moduleMetadata` depuis **`@storybook/angular-vite`**, jamais depuis `@storybook/angular` — ce dernier n'est pas installé, il entre en conflit de peer dependency avec le pipeline `@angular/build` d'Angular 22 (il réclame `@angular-devkit/build-angular@^21`). `@storybook/angular-vite` réexporte les mêmes types.
- **Stories `Sombre`** : appliquer le décorateur `darkTheme` de `preview.ts`, jamais `parameters.backgrounds` seul — ce dernier ne change que la couleur du canvas et laisse les tokens en thème clair, ce qui donne une story mensongère.
- **Limite mesurée d'axe, à ne pas ignorer** : axe **n'infère pas** le rôle implicite d'un élément personnalisé inconnu. Vérifié empiriquement dans cet environnement — `aria-prohibited-attr` se déclenche sur `<div role="generic" aria-label="x">` mais **pas** sur `<gbt-icon aria-label="x">`. Or l'hôte de chaque composant de Gabarit est un élément personnalisé : **aucune assertion ARIA portant sur l'hôte ne doit reposer sur axe**. L'attribut se vérifie directement, par assertion sur le DOM.
- **Zéro violation `axe-core`** sur chaque composant. L'automatisation ne couvre qu'environ 30 % des critères RGAA : chaque composant porte en plus une grille d'audit manuelle dans son dossier, en `AUDIT.md`.
- Commits en français, format Conventional Commits, un commit par tâche minimum.

- [ ] **Step 4: Ne pas embarquer la police ni les utilitaires de mise en page**

Deux blocs de la source sont volontairement laissés à l'application, et c'est une décision à ne pas contourner :

- **`@font-face` Inter** (lignes 156–162) pointe vers `/fonts/inter/Inter-Regular.woff2`, un chemin absolu propre à l'application. Une librairie qui déclare cette règle casse chez tout consommateur qui ne sert pas la police à cette adresse exacte. Les tokens gardent `--font-family`, l'application déclare la police.
- **`.container`, `.d-flex`, `.justify-content-*`, `.align-items-*`, `.gap-*`, `.mb-3`, `.pb-3`** (lignes 164–215) sont des classes globales non préfixées. Une librairie qui les publie entre en collision avec le CSS de n'importe quelle application. Elles restent dans Hangar (voir tâche 9).

Aucun fichier à écrire pour cette étape — c'est une vérification : `grep -c 'font-face\|d-flex' projects/gabarit/src/lib/tokens/*.scss` doit retourner `0` pour chaque fichier.

const semantic = readFileSync(join(DIR, '_semantic.scss'), 'utf8')

/** Résout `var(--grey-500)` ou `#rrggbb` en couleur hexadécimale. */
function resolve(value: string): string {
  const trimmed = value.trim()
  if (trimmed.startsWith('#')) return trimmed
  const ref = /var\(--([a-z0-9-]+)\)/.exec(trimmed)
  if (!ref) throw new Error(`valeur non résolue : ${value}`)
  const found = new RegExp(`--${ref[1]}:\\s*(#[0-9a-fA-F]{6})`).exec(palette)
  if (!found) throw new Error(`token de palette introuvable : --${ref[1]}`)
  return found[1]
}

/** Lit un token sémantique dans le bloc clair ou dans le bloc sombre. */
function token(name: string, theme: 'light' | 'dark'): string {
  const darkIndex = semantic.indexOf('@media (prefers-color-scheme: dark)')
  const scope = theme === 'light' ? semantic.slice(0, darkIndex) : semantic.slice(darkIndex)
  const matches = [...scope.matchAll(new RegExp(`--${name}:\\s*([^;]+);`, 'g'))]
  if (matches.length === 0) {
    if (theme === 'dark') return token(name, 'light')
    throw new Error(`token introuvable : --${name} (${theme})`)
  }
  return resolve(matches[matches.length - 1][1])
}

function luminance(hex: string): number {
  const channels = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255)
  const linear = channels.map((c) => (c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4))
  return 0.2126 * linear[0] + 0.7152 * linear[1] + 0.0722 * linear[2]
}

function ratio(a: string, b: string): number {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x)
  return (hi + 0.05) / (lo + 0.05)
}

import axe from 'axe-core'

/**
 * Passe le DOM d'un composant au moteur axe et échoue s'il reste la moindre
 * violation. axe ne couvre qu'environ 30 % des critères RGAA — c'est un
 * filet, pas une preuve de conformité. Le reste se vérifie à la main, via
 * l'AUDIT.md de chaque composant.
 */
export async function expectNoA11yViolations(element: HTMLElement): Promise<void> {
  const results = await axe.run(element, {
    runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'] },
  })
  if (results.violations.length > 0) {
    const detail = results.violations
      .map(
        (v) =>
          `${v.id} (${v.impact}) — ${v.help}\n    ${v.nodes.map((n) => n.html).join('\n    ')}`,
      )
      .join('\n  ')
    throw new Error(`Violations d'accessibilité :\n  ${detail}`)
  }
}

```typescript
import { Injectable } from '@angular/core'
import { BUILT_IN_ICONS } from './built-in-icons'

/**
 * Registre d'icônes de l'application. Gabarit y dépose les quelques icônes
 * dont ses propres composants ont besoin ; l'application enregistre les
 * siennes au démarrage et peut remplacer les intégrées.
 *
 * Le markup attendu est le **contenu intérieur** d'un `<svg>` lucide —
 * `<path .../>`, `<circle .../>` — sans la balise `<svg>` elle-même, que
 * `gbt-icon` fournit avec ses attributs de tracé.
 */
@Injectable({ providedIn: 'root' })
export class IconRegistry {
  private readonly icons = new Map<string, string>(Object.entries(BUILT_IN_ICONS))

  register(name: string, svgInnerMarkup: string): void {
    this.icons.set(name, svgInnerMarkup)
  }

  registerAll(icons: Record<string, string>): void {
    for (const [name, markup] of Object.entries(icons)) {
      this.icons.set(name, markup)
    }
  }

  get(name: string): string | null {
    return this.icons.get(name) ?? null
  }
}
```

## Ce que ce plan ne couvre pas

- **La couche dataviz** — primitives (`linearScale`, `niceTicks`, `timeTicks`, formats, `linePath`), `chart-frame`, la réécriture de `line-chart` et `bar-chart`, et les nouveaux `sparkline`, `timeline-chart`, `funnel-chart`, `dimension-card`. C'est l'objet du plan 0.2, et c'est la moitié du projet.
- **`stat-tile`, `status-pill`, `empty-state`, `date-range-picker`** — également 0.2.
- **La palette catégorielle de séries** — nécessaire aux graphiques, donc 0.2.
- **L'accessibilité des composants de dataviz** — un graphique en SVG est
  invisible pour un lecteur d'écran s'il n'expose pas ses données en table
  masquée, et la palette catégorielle de séries doit satisfaire le critère
  3.3 à 3:1 tout en restant distinguable en deutéranopie. Traité dans le plan
  0.2, avec la couche dataviz elle-même.
- **La migration de FerrisGit** — chantier court à cinq composants, après la
  0.2. Elle devra appliquer les mêmes correctifs qu'à l'étape 7 de la tâche 9.
- **L'ajout des fichiers `LICENSE` AGPL-3.0 à Hangar, FerrisGit et FerrisTrace** — signalé comme préalable dans la spec, mais hors du périmètre de ce plan.
