# Gabarit for WinUI 3 (Windows)

Gabarit's look for WinUI 3, from SkollN's design (the reference), as XAML resources: they serve an app written in
Swift (swift-winrt) as well as one in C#.

| File                       | What                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `Resources/Gabarit.xaml`   | Generated by `tools/tokens.py`: the colours by role (light and dark), the palette, radii, spacing, text styles, and WinUI's own control resources in Gabarit's colours (ToggleSwitch, TextBox, ComboBox, Slider, ListView, the accent). |
| `Resources/Controls.xaml`  | Gabarit's buttons (`GButtonPrimaryStyle`, `…Secondary…`, `…Ghost…`, `…Danger…`, `…Destructive…`, `…Regular…`), the close cross, the windows' dark header, the rail, cards, rows, badges, passing messages. It merges `Gabarit.xaml`. |
| `Resources/Fonts`          | IBM Plex (SIL Open Font License).                                                                             |

Copy `Resources` into the app as `Gabarit/` (content files), and merge `Controls.xaml` after WinUI's own resources:

```xml
<ResourceDictionary.MergedDictionaries>
    <XamlControlsResources xmlns="using:Microsoft.UI.Xaml.Controls"/>
    <ResourceDictionary Source="ms-appx:///Gabarit/Controls.xaml"/>
</ResourceDictionary.MergedDictionaries>
```

The windows, as on the Mac (`GWindow`, `GAppShell`): extend the content into the title bar
(`AppWindow.TitleBar.ExtendsContentIntoTitleBar = true`), put a `Grid` with `GWindowHeaderStyle` on top (52 high, dark,
room for the system's caption buttons and their Snap Layouts on the right) and give it to `Window.SetTitleBar`. The
main window: that header as its top band, a `StackPanel` with `GRailStyle` on the left, and the page in a `Border` with
`GShellPageStyle` (its rounded top-left corner). Mica or Acrylic can show behind the frame; Gabarit stays flat
everywhere else.

The pointer: Windows keeps the arrow over buttons (its own convention); an app that wants the pointing hand sets
`ProtectedCursor` in code, XAML cannot.

Not yet checked on Windows: these resources are well-formed and every reference resolves (CI), but they still have to
be tried in a WinUI 3 app on the Windows PC.
