# RGAA Audit — PasskeySettings

Checked against RGAA 4.1.2 by the specs (`passkey-settings.spec.ts`, jsdom, including axe-core runs
of the main states), by the play functions of the `Auth/PasskeySettings` stories (`Loading`,
`Failed`, `List`, `LongName`, `Empty`, `Unsupported`, `Unavailable`, `AddForm`, `AddFormFirstKey`,
`Busy`, `WrongPassword`, `AddCancelled`, `AlreadyRegistered`, `Added`, `DeletePrompt`,
`DeleteConfirm`, `LastFactorWarning`, `LastFactorPrompt`, `AddHeldBack`, `DeleteWrongPassword`,
`Dark`, `PhoneWidth`, `Localised`), and by code review (`passkey-settings.ts`,
`passkey-settings.html`, `passkey-settings.scss`). The layout checks (overflow, row width, one-line
names, 44 px targets in a window of 480 px or less) only exist in the stories: they run in a real
browser, in Storybook or its test runner.

## Externalized strings

Every user-facing string is in `PasskeySettingsLabels` (`auth-labels.ts`), English by default
(`DEFAULT_PASSKEY_SETTINGS_LABELS`): the application overrides them for the whole kit with
`provideAuthLabels({ passkeySettings: { … } })`, and per instance with the `labels` input, which wins
string by string (both verified by the spec). Strings that depend on data are functions: `added` and
`lastUsed` receive whether the date is shown as a date (verified), `deleteKey`, `passkeyAdded`,
`passkeyGone`, `deleteLead`, `deleteDialogMessage` (with the last-factor flag) and `nameTooLong`. The
default passkey name is a label too (`defaultPasskeyName`), and is the name sent to the server for
an unnamed key (verified). Dates follow the `locale` input, else `LOCALE_ID` (verified). The
`Localised` story renders the component in French through `labels` and `locale`.
