# RGAA Audit — AuthLogin

Checked against RGAA 4.1.2 by the spec (`login.spec.ts`, jsdom, with axe-core on seven
states), by the play functions of the `Auth/AuthLogin` stories (`Default`,
`WithRegistrationLink`, `Challenge`, `ChallengeBackupCode`, `ChallengeError`,
`ChallengeExpired`, `ChallengePasskey`, `ChallengeBoth`, `ChallengePasskeyUnsupported`,
`PasskeyCancelled`, `PasskeyRefused`, `PasskeyPrompt`, `Enrollment`, `LoginFailure`,
`LoginServerError`, `LoginRateLimited`, `Submitting`, `Phone`, `PhoneChallenge`, `Dark`,
`DarkChallenge`, `Localised`, `LocalisedChallenge`) and by code review (`login.ts`,
`login.html`). The embedded enrolment (`gbt-mfa-enrollment`), the panel and the footer have
their own audits; only what this page adds is covered here.

## Externalized strings

Every string of the page is in `LoginLabels` (`auth-labels.ts`), with English defaults in
`DEFAULT_LOGIN_LABELS`: headings and intros of each state, field labels, the show/hide
password labels, button texts and loading labels, the registration prompt, the "or" divider,
the passkey prompt note, and every error and notice. They are overridden per page with the
`labels` input, or once for the application with `provideAuthLabels({ login })` (the input
wins, string by string: spec). The registration link's text is the application's own
(projected). The embedded enrolment reads `provideAuthLabels({ mfaEnrollment, totpQr,
backupCodes })`. The `Localised` stories render the whole page in French.
