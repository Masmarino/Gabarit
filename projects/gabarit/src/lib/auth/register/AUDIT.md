# RGAA Audit — AuthRegister

Verified against RGAA 4.1.2 by `register.spec.ts` (jsdom, axe-core through `expectNoA11yViolations`,
contrast rule off), by the play functions of the `Auth/AuthRegister` stories (`Default`, `Loading`,
`FieldErrors`, `Errors`, `RateLimited`, `ServerError`, `Submitting`, `Disabled`, `Enrollment`,
`EnrollmentWithPasskeys`, `EnrollmentWithoutPasskeys`, `Created`, `Dark`, `Phone`, `Localised`), and by
code review (`register.ts`, `register.html`, `register.scss`). The embedded enrolment has its own audit
(`gbt-mfa-enrollment`); only its hand-off is covered here.

## Externalized strings

Every user-facing string of the page is a `RegisterLabels` member with an English default
(`DEFAULT_REGISTER_LABELS` in `auth-labels.ts`): headings and intro, the loading text, the closed and
created states (including the "setup has expired" prefix and the "Your username:" line), field labels
and hints (`passwordHint` and `passwordTooShort` take the minimum length), the password toggle's names,
the button and its loading label, the footer's "Already have an account?", every field error and every
server failure. An application overrides them once with `provideAuthLabels({ register })` and per
instance with the `labels` input, which wins string by string (both verified in `register.spec.ts`;
the French strings of the `Localised` story). The sign-in link's text is the application's own
(projected). The enrolment's strings are `MfaEnrollmentLabels` (`provideAuthLabels({ mfaEnrollment })`).
