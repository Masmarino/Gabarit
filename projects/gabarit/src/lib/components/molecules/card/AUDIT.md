# RGAA Audit — Card

Verified against RGAA 4.1.2 by exercising `Molecules/Card` in
Storybook (stories `NoTitle`, `WithTitleAndIcon`, `Hoverable`, `Outlined`,
`DescriptionAndCount`, `HeaderActions`, `Flush`, `FlushElevated`, `Tones`,
`Selected`, `CustomHeader`, `LinkHref`, `LinkProjected`,
`LinkWithSwitchAndCheckbox`, `FlexColumnWithGap`, `Dark`) in light, dark and
at 375 px, by `card.spec.ts` and by `tokens/contrast.spec.ts`, and by code
review (`card.ts`, `card.html`, `card.scss`).

The header is a plain heading **above** the card's box (a sibling, no
background, border or radius of its own); the box holds the body and
carries the selection and the link target.

## Checklist

| Criterion   | Short title                             | Verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Result                            |
| ----------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 3.1         | Information not conveyed by color alone | `hoverable` changes the drop shadow (`box-shadow`) on hover, not just a color. `tone` colours the header's icon and title, and never comes without an icon: the given `icon`, or the tone's own (`check-circle` / `alert-triangle` / `alert-circle`, the icons of `gbt-alert`) — the same icon + colour pairing as `gbt-alert`; the title text carries the meaning. `selected` adds a thicker ring (2px vs 1px edge) AND a visually hidden `selectedLabel` read by screen readers, not only a colour. With a custom `[card-header]` the tone only sets `data-tone` (no colour, no icon): a consumer who styles it owns the pairing (README, "Tone"). Spec: "pairs the tone with an icon".                                       | Compliant                         |
| 3.2         | Text contrast                           | Covered by `contrast.spec.ts` (`--text-secondary` on `--bg-principal`, `--text-primary` for the title). The header has no background: its text is also measured on an app-shell panel (`--bg-panel`), both themes: title `--text-primary`, description and neutral icon `--text-secondary`, count pill (`--text-primary` over an 8% wash of `--border-color`) ≥ 7:1. Toned title and icon (`--color-*-text`, `gbt-badge`'s outline pair): ≥ 7:1 on the page and on a panel. Selected wash (box only): `--primary` at 4% over the page — `--text-primary`, `--text-secondary` and `--primary` ≥ 7:1 on it, both themes.                                                                                                         | Compliant                         |
| 3.3         | Component contrast                      | `elevated`: the card is set apart from its background by `box-shadow` (`--site-shadow-sm`), not by a colored border — the 3:1 threshold for component borders doesn't apply to a shadow-only boundary. `outlined`: the edge is a quiet hairline (`--gbt-card-border`, `--border-color` at 60%) — the card is a non-interactive container whose content never depends on the edge, so the same 3:1 rule doesn't apply. `tone` never tints the edge. The link mode's focus ring is `--primary` (7:1 on the page).                                                                                                                                                                                                                | Compliant / Not applicable        |
| 6.1 / 6.2   | Explicit link / link name               | In link mode the anchor is the heading text (`linkLabel` as `aria-label` only when there is none: with a heading the visible text stays the name, WCAG label in name) — an explicit name, never the card's whole content. Spec: `link-name` clean (axe) for the heading and the label-only overlay.                                                                                                                                                                                                                                                                                                                                                                                                                             | Compliant                         |
| 7.1 / 12.8  | Nested interactive content               | Stretched-link pattern: the anchor contains only text, all other controls are siblings lifted above the overlay. The overlay normally covers the box only (the host is a grid, the overlay names the box's area); when that grid does not apply (e.g. `display` overridden on the host) it covers the header row too, and the header's controls stay operable because they are lifted above it like the body's (`card.spec.ts` pins the rule and that it reaches a `[card-header-actions]` button; the `LinkProjected` story's play function hit-tests the box and the action). `card.spec.ts` asserts the anchor has no interactive descendant and axe's `nested-interactive` passes with a button and a second link in the card. | Compliant                         |
| 7.3         | Keyboard operable                       | One tab stop for the card link, then each projected control in DOM order (header actions, then the box's controls); Enter activates the anchor natively.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Compliant                         |
| 9.1         | Heading hierarchy                       | `headingLevel` (default `2`, range 1–6) drives the rendered heading level via a `@switch` — verified by `card.spec.ts` ("renders an h2 by default", "respects the requested heading level") and manually in Storybook for `headingLevel=3`. The icon sits beside the heading (`aria-hidden`), the description is a `<p>`, and the count is inside the heading so its text is announced with it.                                                                                                                                                                                                                                                                                                                                | Compliant                         |
| 10.7        | Visible focus indicator                 | The card sets no `tabindex`: `hoverable` is only a `pointer` cursor and a hover shadow, the card itself never receives keyboard focus (it carries no action of its own — a button or link projected inside it manages its own focus). In link mode, the box takes the ring (`outline: 2px solid var(--primary)`, `outline-offset: -2px`, drawn inside the box's edge because the elevated box clips its overflow; a `selected` card moves it to `-5px` so it is not hidden under the 2px selection ring — mirrored on the host for a heading link, whose overlay is outside the box); focus never lands on the container itself. Verified with the Tab key in Storybook.                                                       | Compliant / Not applicable        |
| 10.11       | 320px reflow                            | Viewport set to 320×600 on the `WithTitleAndIcon` story: `scrollWidth === clientWidth`, no horizontal scroll. The host grid's column is `minmax(0, 1fr)`; titles wrap (`overflow-wrap: anywhere`), the actions keep their size; grid stories at 375px show no horizontal scroll.                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Compliant — verified              |
| 10.12       | Redefinable text spacing                | Injected stylesheet (`line-height:1.5`, `letter-spacing:0.12em`, `word-spacing:0.16em`) on `WithTitleAndIcon`: title and projected content stay readable, no truncation, screenshot on file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Compliant — verified              |
| 12.6        | `[card-header]` slot                    | Not applicable to the component itself: the consumer's header markup owns its heading level; the doc asks for a heading element inside the slot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Delegated                         |
| WCAG 2.4.11 | Focus not obscured                      | Not applicable — the card never takes focus itself (see 10.7).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Not applicable to this component  |
