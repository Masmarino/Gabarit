# RGAA Audit — Button

Verified against RGAA 4.1.2 by exercising `Atoms/Button` in Storybook
(stories `Nominal`, `Empty`, `Dense`, `Dark`) and by code review
(`button.ts`, `button.html`, `button.scss`).

| Criterion   | Short title                             | Verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Result                                                   |
| ----------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 3.1         | Information not conveyed by color alone | `Dense` story: `Primary`/`Secondary`/`Danger` each carry a distinct textual label ("Danger") — the red color is redundant with the text, never the sole carrier. In icon-only mode (`Empty` story), meaning depends on the icon the consumer chose, outside the component's control.                                                                                                                                                                                                                                                                           | Compliant in nominal use                                 |
| 3.2         | Text contrast                           | Covered by `contrast.spec.ts` (pairs `--text-on-primary`/`--primary`, `--text-on-error`/`--color-error-fill`, etc.). `button.scss` paints the `danger` fill with `--color-error-fill`; `--text-on-error` on that fill measures 7.04:1 light / 7.01:1 dark.                                                                                                                                                                                                                                                                                                     | Compliant                                                |
| 3.3         | Component contrast                      | No border on `primary`/`danger` (solid fill); `secondary` has a `--border-color` outline measured at 3.03:1 in `_semantic.scss`. No dedicated `:focus`/`:focus-visible` style — relies on the browser's default outline, not suppressed.                                                                                                                                                                                                                                                                                                                       | Compliant                                                |
| 7.3         | Keyboard- and pointer-operable          | Native `<button type="button">`, no `keydown`/`keypress` handler in `button.ts` that would intercept or block activation — Enter and Space trigger the browser's native `click` event, which calls `handleClick()` → `clicked.emit()`. Verified by code review; the `<button>`'s native behavior is not altered by the component.                                                                                                                                                                                                                              | Compliant (code review)                                  |
| 10.7        | Visible focus indicator                 | No `outline: none`/`outline: 0` rule in `button.scss`: the browser's default focus outline stays active across all three variants, in both themes (the component sets no background color that would overwrite it).                                                                                                                                                                                                                                                                                                                                            | Compliant (code review — default outline not suppressed) |
| 10.11       | 320px reflow                            | Viewport set to 320×600 on the `Nominal` story (long text) and `Dense`: `document.documentElement.scrollWidth === clientWidth`, no horizontal scroll.                                                                                                                                                                                                                                                                                                                                                                                                          | Compliant — verified                                     |
| 10.12       | Redefinable text spacing                | Injected stylesheet (`line-height:1.5`, `letter-spacing:0.12em`, `word-spacing:0.16em`) on the `Nominal` story with long text: the label wraps within the container without truncation or overlap (`span.scrollWidth === span.clientWidth`), screenshot on file.                                                                                                                                                                                                                                                                                               | Compliant — verified                                     |
| 11.9        | Relevant button label                   | `ariaLabel` set via `[attr.aria-label]` on the `<button>`; tested in icon-only mode (`button.spec.ts` + a dedicated axe test). Nothing stops a consumer from omitting `ariaLabel` with `text=''`: the component doesn't enforce it at compile time. The visible text label (`<span>{{ text() }}</span>`) renders unconditionally even while `loading`: the spinner and its `sr-only` `loadingLabel` are added in front of it rather than replacing it, so a loading button keeps both its visible label and its screen-reader announcement (`button.spec.ts`). | Compliant for the documented usage; no runtime safeguard |
| 13.8        | Controllable moving content             | `.gbt-button__spinner`'s animation respects `@media (prefers-reduced-motion: reduce) { animation: none; }` — the incomplete ring stays visible at rest, and the hidden `loadingLabel` (default `'Loading'`, tested in `button.spec.ts`) continues to carry the information for screen readers. Verified by reading the compiled CSS rule (`getComputedStyle` confirms `animationDuration: 0.6s` with no reduced preference); actually toggling `prefers-reduced-motion` could not be emulated with the browser tooling available for this audit.               | Compliant                                                |
| WCAG 2.5.8  | 24×24px target size                     | Measured under real conditions in Storybook (`getBoundingClientRect`) on the `small` size, worst case short text and icon-only: `A` → 33.4 × 27px; icon-only (`check`, `ariaLabel="Valider"`) → 48.25 × 28.25px. Both exceed 24×24px.                                                                                                                                                                                                                                                                                                                          | Compliant                                                |
| WCAG 2.4.11 | Focus not obscured                      | No scrolling container or `sticky`/`fixed` element in the component or its Storybook context that could obscure focus.                                                                                                                                                                                                                                                                                                                                                                                                                                         | Not applicable to this component                         |
