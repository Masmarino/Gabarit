# RGAA Audit — gbt-gauge-bar

Verified against RGAA 4.1.2 by reading `gauge-bar.ts`, `gauge-bar.html`,
and `gauge-bar.scss`, by running `gauge-bar.spec.ts`,
`contrast.spec.ts`, and `token-usage.spec.ts`
(`projects/gabarit/src/lib/tokens/`), and by opening Storybook directly
in a browser at 320px — see criterion 10.11. Each row names the test
that produced it, or says none does.

`gbt-gauge-bar` assembles no base building block: neither
`gbt-chart-frame`, `gbt-chart-table`, nor `ChartContext`. Nothing here
is therefore inherited from `chart-frame/AUDIT.md`, except the color
tokens, shared by the whole library.

## Checklist

| Criterion                                      | Verdict | Verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 — text alternative to non-text information | ✅      | No image: the bar is a `div`, and the value is displayed as text. `role="progressbar"` carries `aria-label`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-valuetext` — verified by `gauge-bar.spec.ts`, test "presents itself as a progress bar, carried by the track and not the root", which reads all five attributes. **The scale: `aria-valuenow`, `aria-valuemin`, and `aria-valuemax` are expressed as a percentage (0–100), not in the consumer's own scale.** With `[max]="500"` and `[value]="62"`, a screen reader reads `aria-valuenow="12.4"` on a 0–100 scale — neither "62" nor "62 out of 500". Only `aria-valuetext` carries the human-readable value, via `formattedValue()` ("62 GB / 100 GB", for instance): it, and only it, is what an application displaying the ARIA rather than having it announced must read. **No `sr-only` table, deliberately**: it would duplicate a value already readable as text, and the component would announce it twice. **The role lives on `.gbt-gauge-bar__track`, not on the root**: `progressbar` is "Children Presentational", and set on the root it would erase the severity label from the accessibility tree — severity would then be carried by color alone. `gauge-bar.spec.ts` asserts that the root carries no `role`, and that `.gbt-gauge-bar__tier` isn't contained within the track. |
| 3.1 — information not by color alone           | ✅      | The severity label is spelled out in full next to the value, at every threshold: 50% → no label, 70% and 89% → "Avertissement", 90% and 100% → "Critique" — both bounds of each tier (`it.each`, `gauge-bar.spec.ts`), including with custom `thresholds`. The fill's hue only doubles up on this text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 3.2 — text contrast                            | ✅      | `contrast.spec.ts` measures `text-primary` (label) and `text-secondary` (value) at ≥ 7:1 on a light background **and** a dark background, as well as `color-warning-text` and `color-error-text` — the two severity-label colors — at the same threshold in both themes. No composited surface is involved in `gbt-gauge-bar`'s own rendering, unlike `dimension-card` and `funnel-chart` — but `contrast.spec.ts` only measures this text against `bg-principal`, while the actual surface under a `gbt-gauge-bar` is chosen by the consuming application: placed on a panel (`bg-panel`), the severity label measures 6.46:1 in light mode — below the targeted 7:1 but still above the 4.5:1 AA threshold. `token-usage.spec.ts` separately forbids any `color:` from using a `*-base` token, which is what keeps `.gbt-gauge-bar__tier` on `--color-error-text` rather than `--color-error-base` (3.78:1).                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

The track (`--bg-hover`) is an `rgba(...)` overlay outside `contrast.spec.ts`'s `resolve()` scope, so it isn't measured — the track carries no information, so this has no compliance consequence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 3.3 — `*-base` exemption on a fill             | ✅      | `token-usage.spec.ts` forbids `background` with a `*-base` token. The three lines of `gauge-bar.scss` that paint the fill carry the `// token-graphique-sans-texte` marker at the end of the line: the exemption is explicit, matched one line at a time, and refused outright for `color`, `border-color`, and `outline-color`. The 3:1 threshold is the right one here — the fill carries no text, which lives in the header, above the track.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 10.11 — 320px reflow                           | ✅      | Storybook opened directly in a browser (`npm run storybook`, port 6006), viewport 320 × 700, on `Atoms/Dataviz/GaugeBar → Nominal`, `Critical`, and `Dense`. ## What this audit doesn't cover

- **The interaction criteria (7.1, 10.13, 12.11) don't apply.**
  `gbt-gauge-bar` has no event handler, no focusable element, no
  tooltip: it's a pure display component. Measured in the browser on
  `Atoms/Dataviz/GaugeBar → Dense`: `[tabindex]` counts **0** elements
  in the whole component. There is therefore no keyboard path to check,
  and no mouse path lacking a keyboard equivalent — the non-applicability
  comes from the component offering no interaction at all, a deliberate
  choice, not from an incomplete implementation.
- **The track (`--bg-hover`) is measured by no test**: it's an
  `rgba(...)` overlay that `contrast.spec.ts`'s `resolve()` can't
  handle. No compliance consequence — the track is a plain groove,
  carrying no information.
- **Actual rendering by a screen reader hasn't been verified.**
  `role="progressbar"` on the track and the severity label outside that
  element are proven in the DOM by `gauge-bar.spec.ts`, and the "has no
  violation detected by axe" test passes; but no listening session with
  VoiceOver, NVDA, or Orca took place.
- **`aria-valuetext` receives `formattedValue()` as-is.** If the
  application passes it a meaningless string, the announcement will be
  too; no test can check the quality of a consumer-supplied string.
- **The `:active` and `:disabled` states aren't covered** — the
  component has neither, but no hover state is defined on its track
  either (see `README.md`, "Known limitations").
