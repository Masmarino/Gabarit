# RGAA Audit — Input

Verified against RGAA 4.1.2 by exercising `Atoms/Input` in Storybook
(stories `Empty`, `Filled`, `Password`, `Error`, `Dark`) and by code
review (`input.ts`, `input.html`, `input.scss`).

| Criterion   | Short title                    | Verification                                                                                                                                                                                                                                                                                                                                  | Result                                                      |
| ----------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 3.2         | Text contrast                  | Covered by `contrast.spec.ts`; `--color-error-base`, used for the error message, isn't explicitly listed there (graphic-only 3:1 threshold, not text) — worth watching if a future component reuses this color for normal-size text.                                                                                                          | Compliant for the tested tokens                             |
| 3.3         | Component contrast             | `--border-color` (3.03:1, light) / dark `--border-color` (3.01:1) on the field's outline; `:focus-visible` adds a dedicated `2px solid var(--primary)` outline, offset by `1px` — above the minimum.                                                                                                                                          | Compliant                                                   |
| 7.3         | Keyboard- and pointer-operable | Input tested via the native `input` event (`input.spec.ts`) — the functional equivalent of keystrokes, no handler intercepts it. The password-visibility toggle is a real `<button type="button">`, keyboard-activatable by nature.                                                                                                           | Compliant                                                   |
| 10.7        | Visible focus indicator        | `input.scss` explicitly removes `:focus { outline: none }` **but** replaces it with `:focus-visible { outline: 2px solid var(--primary); outline-offset: 1px }` — the outline disappears only for mouse activation, stays for keyboard. Verified by reading the compiled CSS (correct `outline`, `outlineWidth`, `outlineOffset`).            | Compliant                                                   |
| 10.11       | 320px reflow                   | Viewport set to 320×600 on the `Error` story: `scrollWidth === clientWidth === 320`, no horizontal scroll, error message not truncated.                                                                                                                                                                                                       | Compliant — verified                                        |
| 10.12       | Redefinable text spacing       | Injected stylesheet (`line-height:1.5`, `letter-spacing:0.12em`, `word-spacing:0.16em`) on `Error`: label, placeholder, and message stay readable, screenshot on file.                                                                                                                                                                        | Compliant — verified                                        |
| 11.1        | Label presence                 | `label()` is optional but, as soon as it's set, associated via `[for]="id()"` / `[id]="id()"` with an auto-generated id (`gbt-input-N`) — no orphan label possible on the component's side. If `label` is omitted, the field loses its accessible name: the consumer's responsibility.                                                        | Compliant when `label` is provided                          |
| 11.2        | Label relevance                | The label's text is entirely delegated to the consumer (`input()<string>`) — no hardcoded string, so nothing to check on the component's side.                                                                                                                                                                                                | Compliant (delegated)                                       |
| 11.4        | Label position                 | `<label>` rendered before `<input>` in the flow (`flex-direction: column`), above the field — the conventional position for a text field.                                                                                                                                                                                                     | Compliant                                                   |
| 11.10       | Field grouping                 | Single-field component, no `fieldset`/`legend` — not applicable.                                                                                                                                                                                                                                                                              | Not applicable to this component                            |
| 11.11       | Label/format with a hint       | `errorMessage` linked via `[attr.aria-describedby]="id() + '-error'"` and `role="alert"` — the hint/error is announced, not just displayed. The `placeholder` stays supplementary (never the sole carrier of an instruction, since `label` is always the primary accessible name).                                                            | Compliant                                                   |
| 11.13       | Relevant `autocomplete`        | `autocomplete` is an input passed through as-is via `[attr.autocomplete]`, defaulting to `'off'` — the component provides the mechanism, an RGAA-compliant value (`name`, `email`, etc.) remains the consumer's responsibility per field.                                                                                                     | Mechanism compliant; value is the consumer's responsibility |
| WCAG 2.5.8  | 24×24px target size            | `.gbt-input__toggle` (the password-visibility button) carries an absolutely-positioned `::before` sized to `max(100%, 24px)`, extending its target area to at least 24×24px with no change to the visible button box (28.66 × 18.66px). Measured in Storybook (`Password` story, `getComputedStyle(button, '::before')`): **28.6641 × 24px**. | Compliant                                                   |
| WCAG 2.4.11 | Focus not obscured             | No scrolling container specific to the component.                                                                                                                                                                                                                                                                                             | Not applicable to this component                            |

Dark mode is visually confirmed in Storybook: on the `Dark` story,
with `data-theme="dark"` set, `body` renders `rgb(13, 27, 36)`, the
label `rgb(158, 189, 207)` (**8.87:1**), typed text
`rgb(247, 249, 251)`, and the field's border `rgb(67, 106, 128)`.
Token contrast is otherwise covered by `contrast.spec.ts`,
independently of this rendering.
