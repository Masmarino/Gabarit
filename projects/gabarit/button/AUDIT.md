# RGAA Audit — Button (`gbt-button` / `a[gbtButton]`)

Verified against RGAA 4.1.2 by exercising `Atoms/Button` in Storybook
(stories `Nominal`, `Empty`, `Dense`, `Sizes`, `Variants`, `Ghost, ghost-danger and link in a list row`,
`Icon-only squares`, `Toggle`, `Disclosure`, `Block`, `Large size reaches 44px`, `Dark`, `VariantsDark`, `ToggleDark`,
and the anchor-form stories `Anchor: nominal`, `Anchor: variants`, `Anchor: sizes`,
`Anchor: disabled (aria-disabled, no navigation)`, `Anchor: block (full width)`,
`Anchor beside a gbt-button (same box)`, `Anchor: dark`) and by code review (`button.ts`, `button.html`,
`button.scss`, the shared `_button-look.scss`).

`Button` is one Angular class with two selectors (`gbt-button, a[gbtButton]`): the button-form
findings and the anchor-form findings below both apply to it, since both forms share the same look
mixin and the same variant/size class computation.

## Notes

- A `disabled` link stays an `<a>` with an `href`: the attribute belongs to
  the consumer. Assistive technology reads "link, dimmed/unavailable" through
  `aria-disabled`; only the click is blocked.
- Angular folds every `(click)` handler of an element into one DOM listener
  that cannot be stopped from a host binding, which is why the disabled guard
  is a capture-phase listener registered in the constructor.
- The button and anchor forms are one Angular class (`selector: 'gbt-button,
a[gbtButton]'`); which behaviour applies is decided once, in the
  constructor, from `ElementRef.nativeElement.tagName`. Every input/output
  irrelevant to a given form (e.g. `type` or `loading` on the anchor,
  `clicked` never firing there) is simply inert on that form — it changes no
  accessibility guarantee documented above, since the anchor never renders
  the button-only markup and the button never runs the anchor-only listeners.
